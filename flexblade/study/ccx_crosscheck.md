## Notes and caveats

* **Peak vs p99.** Maximum integration-point values are dominated by re-entrant corners / material
  jumps (bonded, no fillets) and are mesh dependent (winner: blade-1 pa6 max vM 424 -> 474 MPa,
  rod 826 -> 991 MPa when refined). The p99 von Mises is converged to a few % (68 -> 69, TPU 10.8 -> 11.0,
  rod 557 -> 546 MPa) and displacement (1.20 -> 1.24 mm) and the 6x6 stiffness (diagonal within
  1-4 %, hinge-axis stiffness 0.320 -> 0.314 N m/rad) are mesh converged. Use p99 for comparison with beam/section
  models; use max only as a hot-spot flag.
* **Interlayer** `s_build` is the stress along the print build axis (material axis 3) of each element
  set; for the CF rods (build axis arbitrary perpendicular) it is a transverse stress.
* **Utilisations** are against `materials.py`: vM/Xt, tensile build-axis stress/Zt, max principal strain /
  `creep_strain_allow` (the sustained allowable, so >1 only means the centrifugal strain exceeds the
  creep allowable at full rpm, not rupture). They are computed from the unsmoothed peak values.
* **hinge_equiv centrifugal.** The hinge-equivalent flexure has a very soft hinge DOF (about 1.2 N m/rad
  vs a centrifugal torque about the skewed axis): a *linear* analysis predicts 163 mm tip displacement and
  zero-frequency mode (a mechanism) and is discarded; the NLGEOM run converges (6.35 mm) but the mesh is too coarse
  for 0.8 mm plates, so its peak stresses are indicative only. The 6x6 stiffness is linear/unpreloaded
  (centrifugal geometric stiffening not included in it).
* **Frequencies** (winner) are ccx `*FREQUENCY` after the NLGEOM centrifugal step (prestressed, hub core fixed,
  stationary frame). Pairs (151.2/151.5, 370.9/371.8, ...) are the two blades.
* **Method differences worth knowing when comparing against fea.py/beam.py:** straight-edge tet10; blade-side
  of the stiffness run is rigid (blade + root fitting; PA6-CF is ~300x stiffer than the TPU); hub clamped;
  `blade*_shank` parts are dropped (geometry.py builds them with negative volume); fragment slivers
  < 0.05 mm^3 are dropped; all overlaps are given to the highest-priority part as in geometry.PRIORITY.
* **geometry.export_step defect** (not used here): for this design the fused STEP loses the aerodynamic blade
  (fragments of zero volume) and contains an inverted `blade1_shank`; ccx.py therefore rebuilds the lofts in mm
  from `geometry.build_geometry` parts and fragments them itself (works).
* **ccx bug on this machine:** ccx 2.21 with a multithreaded SPOOLES solve is non-deterministic (about 1 run
  in 10 returned a wrong displacement for an identical input: tip deflection off by 50 %); `ccx.run` forces
  `CCX_NPROC_EQUATION_SOLVER=1` (16/16 and 32/32 identical afterwards) while keeping OMP_NUM_THREADS=4 elsewhere.
